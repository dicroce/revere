Licensing TODO
==============

Open licensing issues in what Revere ships, found while building licenses/
(2026-11-07). The goal is that the closed system plugins (revere_cloud,
revere_homekit), which load into revere's process, never share it with
GPL or AGPL code, and that every package carries the notices and source its
components require.

Done so far: FFmpeg is an LGPL build on every platform (v0.0.36), the GPL
GStreamer plugins are gone, and licenses/ (generated from
scripts/licenses/components.json) is installed in every package.


1. Linux tray icon links GPL-3 libraries                        [open, decided: later]
-------------------------------------------------------------------------------------
traypp's Linux backend (dicroce/traypp, tray/src/core/linux/tray.cpp) uses
libayatana-appindicator3, which pulls in libayatana-indicator (GPL-3, the
whole library) and libayatana-ido (GPL-3 menu-item code), per Debian's
copyright files. They load into revere's process. The AppImage bundles them;
the Pi .deb depends on Debian's.

Options:
  a. Rewrite traypp's Linux backend to speak StatusNotifierItem +
     com.canonical.dbusmenu over GDBus (GLib, LGPL) directly. ~500 lines.
     Also drops GTK3 and ~40 libraries (GTK, cairo, pango, atk, X11...) from
     the AppImage. Same desktop support as today (KDE, XFCE, Cinnamon;
     GNOME with the AppIndicator extension). The icon goes over D-Bus as an
     ARGB pixmap (decode the PNG with stb_image).
  b. Move the Linux tray into a separate small executable that talks to
     revere over the local API, as `revere --tray` already does. Keeps
     appindicator/GTK, but outside revere's process.
  c. Ayatana's newer GLib-only libayatana-appindicator-glib, once it's in
     the distributions we build on (not in Debian bookworm or Ubuntu 24.04).


2. YOLOv8n model weights are AGPL-3.0                                       [resolved]
-------------------------------------------------------------------------------------
models/yolov8n.{bin,param} (all packages) are Ultralytics' YOLOv8 weights,
released under AGPL-3.0 (commercial licence sold separately). They're data
loaded by ncnn, not linked code, so how far the AGPL reaches is arguable;
Ultralytics' position is that it covers uses of the model.

Options: swap to a permissively licensed detector (YOLOX, NanoDet,
RT-DETR: all Apache-2.0) and re-tune the motion tiers; buy an Ultralytics
licence; or make the model a separate, optional download.

Resolved: swapped to YOLOX-s (Apache-2.0 weights, Megvii) in
yolox_motion_plugin, converted to ncnn by tools/yolox/export_yolox_ncnn.py.
yolov8_motion_plugin and its weights are removed from the repository (they
are still in git history, from before the switch).


3. Windows FFmpeg carries ~60 extra libraries                                [open]
-------------------------------------------------------------------------------------
BtbN's lgpl-shared n8.1 build statically links aom, dav1d, libass, zmq, srt,
librsvg (with cairo/pango/glib), harfbuzz, ... into its DLLs. They're all
LGPL-compatible and covered by licenses/btbn-deps.txt (600 KB), but Revere
uses almost none of them. Building our own Windows FFmpeg with the same small
configuration as macOS/Linux (scripts/linux/build_ffmpeg_lgpl.sh: openh264,
webp, opus, plus d3d11va/dxva2/nvdec/qsv/amf) would shrink the licence list
and the installer, and make every platform the same FFmpeg.


4. LGPL source: written offer vs. shipping the source                       [open]
-------------------------------------------------------------------------------------
licenses/README.md promises the exact LGPL source on request (a written
offer, LGPL-2.1 section 6c). That's a commitment to keep the source of every
released version available. Simpler and stronger: attach the source
tarballs (FFmpeg n8.1.3, GStreamer, GLib, gettext, BtbN's build scripts at
the commit used) to each GitHub release, and change the README to point
there.


5. Closed plugins' own notices                                              [open]
-------------------------------------------------------------------------------------
revere_cloud statically links libdatachannel, libjuice (MPL-2.0), libsrtp,
usrsctp (BSD) and mbedtls (Apache-2.0). MPL-2.0 is file-level copyleft: the
cloud installers (.run, .command, Windows setup) need those notices and a
pointer to the MPL source files. Same check for revere_homekit.


6. macOS: SDL3 may be missing from the bundle                               [check]
-------------------------------------------------------------------------------------
Homebrew's SDL2 is now sdl2-compat, which loads SDL3 at runtime (dlopen).
libSDL3 isn't in the dylibbundler list, so Vision/revere may fail on a Mac
without Homebrew's sdl3. Test on a clean Mac; if broken, bundle libSDL3 (and
add its licence) or build SDL2 from source as Linux and Windows do.
